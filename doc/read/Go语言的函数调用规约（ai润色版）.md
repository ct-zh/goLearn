# 什么是函数调用规约？

调用规约是一组规则，规定：

1. **参数如何传给函数（寄存器？栈？顺序？）**
2. **返回值通过什么方式返回（寄存器？内存？多个值如何处理？）**
3. **调用时栈如何分配与恢复（Caller 还是 Callee 负责？）**
4. **哪些寄存器需要被保存，哪些可以随意覆盖**

每种语言、每种架构、甚至不同版本的语言都会有不一样的调用规约。

本文的主体以以下环境为基础：

- Go 1.17+（使用 Register ABI）
- AMD64 & ARM64（以 AMD64 为例说明）
- C 使用 System V ABI（Linux/Unix 主流 ABI）

---

# 为什么要理解调用规约？

理解调用规约，你将获得：

✔ **更深刻的逃逸分析理解**（变量为什么会逃逸？）

# 函数调用规约之：参数怎么传？

> 本节目标：  
> **搞清楚 Go 与 C 的函数参数，是如何进入寄存器或栈的。**

Go 1.17+ 使用 **寄存器 ABI**：只要寄存器够，参数都会优先放到寄存器里；寄存器不够才会退回栈。

## 参数传递规则（简明版）

### Go 的参数分配（AMD64，整数类型）

| 参数序号 | 寄存器 |
|---------|--------|
| 第 1 个 | RAX |
| 第 2 个 | RBX |
| 第 3 个 | RCX |
| 第 4 个 | RDI |
| 第 5 个 | RSI |
| 第 6–N 个 | R8, R9, …（视情况而定） |
| 寄存器不够 | Spill 到栈上 |

Go 的参数寄存器顺序并非沿用 System V，而是 Go 编译器（SSA）根据自身优化需求设计的。

### C 的参数分配（System V ABI，AMD64）

| 参数序号 | 寄存器 |
|---------|--------|
| 1 | RDI |
| 2 | RSI |
| 3 | RDX |
| 4 | RCX |
| 5 | R8 |
| 6 | R9 |
| 6 之后 | 栈 |

两种语言使用完全不同的顺序。

---

## 精简 Go 示例：参数进入寄存器

```go
// go_arg.go
package main

func add(a, b int) int { return a + b }

func main() {
	_ = add(1, 2)
}
```

观察汇编：

```sh
go tool compile -S -N -l go_arg.go
```

关键观察点：

- 参数 a → RAX  
- 参数 b → RBX  
- main 负责预留 spill slots  
- add() 内部不处理栈空间

---

## 精简 C 示例：参数进入固定寄存器

```c
// c_arg.c
int add(int a, int b) { return a + b; }

int main() {
    add(1, 2);
}
```

查看汇编：

```sh
clang -S -O0 c_arg.c
```

关键观察点：

- 参数 a → RDI  
- 参数 b → RSI  
- 函数内部不负责清理栈

---

## 本节小结

- Go 和 C 都优先使用寄存器传参，但顺序完全不同  
- Go 的寄存器 ABI 更自由，适合 GC 和栈扩容  
- 寄存器不够都会退回栈  
- 调用者（Caller）分配调用所需的栈空间（下一节会说）

# 函数调用规约之：返回值怎么传？

> 本节目标：  
> **理解返回值如何使用寄存器传回，尤其是 Go 的多返回值。**

Go 的多返回值机制，是它 ABI 设计的核心之一。

## Go 的返回值：直接“平铺”在寄存器里

Go 支持原生多返回值，因此 ABI 采用：

> **多个返回值 → 多个寄存器按顺序分配**

AMD64：

| 返回值序号 | 寄存器 |
|-----------|--------|
| 第 1 个 | RAX |
| 第 2 个 | RBX |
| 第 3 个 | RCX |
| 第 4+ | R8、R9... 或退回栈 |

ARM64 则为 X0、X1、X2……，与 C 的风格类似，但支持更多值。

---

## Go 多返回值示例（精简）

```go
// go_ret.go
package main

func multi() (int, int, int) {
	return 1, 2, 3
}

func main() {
	a, b, c := multi()
	_, _, _ = a, b, c
}
```

关键观察点：

- 返回值分别进入 RAX / RBX / RCX  
- 不需要结构体、不需要临时内存  
- 这就是 Go 原生多返回值的强大之处

---

## C 的返回值：只能一个寄存器

```c
int one() { return 123; }
```

返回值必须：

- 整数 → RAX  
- 浮点 → XMM0  
- 多返回值只能依赖结构体或输出参数

C 无法像 Go 一样直接多寄存器返回。

---

## 小结

- Go 多返回值 = 多寄存器，天然高效  
- C 单返回值 = 只能用 RAX  
- 多返回值需求是 Go ABI 重新设计的重要动因

---

# 函数调用规约之：谁来清理栈？

> 本节目标：  
> **理解哪一方负责恢复栈指针（SP）。**

结论非常关键：

# ✔ Go：Caller 清理栈  
# ✔ C：Caller 清理栈（System V ABI）

Go 和 C 都选择 Caller-Clean 模式。

---

## Caller-Clean 的原因（Go 的视角）

- 支持可变参数更容易  
- 函数内部更干净（无栈清理逻辑）  
- 有利于 GC 的栈扫描  
- 有利于 Go 的栈扩容（stack grow）  
- 调用链统一、更简洁

---

## 精简 Go 示例

```go
func foo(a, b int) int { return a + b }

func main() {
	_ = foo(1, 2)
}
```

观察点：

- main 负责扩展和恢复 SP  
- foo 不处理调用者的栈空间

---

## 精简 C 示例

```c
int foo(int a, int b) { return a + b; }
```

同样：

- main 调整 SP  
- foo 内部不恢复栈

---

## 小结

- Caller 清理栈是 Go/C 的共同选择  
- 对 Go 的 GC 特性极其重要  
- 简化函数内部逻辑，提高可预测性

---

# 函数调用规约之：寄存器的保护责任

> 本节目标：  
> **理解谁负责保护寄存器内容。**

这是 Go 与 C 的最大差异之一。

# ❗ C：Caller-Saved + Callee-Saved 混合模式  
# ❗ Go：几乎全部 Caller-Saved（非常激进）

---

# C 的寄存器保护规则（混合）

| 类型 | 责任方 | 寄存器 |
|------|--------|--------|
| Caller-Saved | 调用者保存 | RAX, RCX, RDX, RSI, RDI, R8–R11 |
| Callee-Saved | 被调用者保存 | RBX, RBP, R12–R15 |

C 的设计目标是：  
让调用者尽可能少担心寄存器被破坏。

---

# Go 的寄存器保护规则（全 Caller-Saved）

Go 的策略非常大胆：

> **除了少量特殊寄存器外，所有寄存器都可以任意破坏。**

意味着：

- Callee 可以随意使用寄存器  
- 不需要保存、不需要恢复  
- Caller 若想保留寄存器内容 → 必须 spill 到栈  
- 运行时（runtime）实现极其简化

为什么 Go 要这么做？

---

# Go 为什么采用全 Caller-Saved？

## 1. 更容易实现 GC

GC 在安全点需要识别寄存器里的指针。

如果 Callee-Saved 把寄存器压栈/恢复，GC 会极难处理。

Caller-Saved 的好处：

- 哪些寄存器存指针只需看 Caller 的 stack map  
- Callee 不会乱动栈上的东西  
- GC 扫描大幅简化

---

## 2. 更容易实现栈扩容（stack grow）

Go 的 goroutine 使用可扩容的栈。

如果 Callee 压栈太多寄存器，会导致栈扩容逻辑异常复杂。

Caller-Saved → 栈内容简单、可预测 → 扩容更轻松。

---

## 3. 为多返回值提供天然支持

C 的 Callee-Saved 会干扰多返回值的寄存器布局。

Go 取消 Callee-Saved → 任意使用寄存器 → 多返回值轻松平铺。

---

## 精简对比示例

### Go

```go
func use() { _ = 1 + 2 + 3 }
```

观察点：

- 不会保存 RBX, R12–R15  
- Callee 可自由覆盖寄存器

### C

```c
int use() { return 1 + 2 + 3; }
```

观察点：

- 如果函数使用 RBX，必须 push/pop 进行保存与恢复

---

## 小结

| 特性 | Go | C |
|------|----|---|
| 寄存器保存方 | Caller | Caller + Callee |
| GC 兼容性 | 极佳 | 一般 |
| 多返回值支持 | 强 | 弱 |
| 栈扩容适配 | 强 | 弱 |

Go 的这种设计高度契合其语言设计目标：  
高并发、轻量线程、可扩容栈、实时 GC。

---

# 全文总结

本文从四个关键维度完整介绍了函数调用规约：

1. **参数怎么传？**  
   Go 使用 RAX/RBX/RCX… 多个寄存器；溢出时使用栈。

2. **返回值怎么传？**  
   Go 原生多返回值 → 多寄存器平铺。  
   C 只有一个返回值（RAX）。

3. **谁来清理栈？**  
   Go 和 C 都是 Caller 清理栈。

4. **寄存器谁负责保护？**  
   Go：几乎所有寄存器 Caller-Saved（为 GC 服务）  
   C：Caller-Saved + Callee-Saved 混合

Go 的调用规约从头到尾都围绕一件事：

> **让并发、GC、可扩容栈成为语言的核心能力。**

理解调用规约，你就理解了 Go 的性能哲学。
